# Rimrooms first-slice Core API source map

**Checked:** 2026-09-28  
**Status:** Static source/metadata reconnaissance only. No Rimrooms code, XML Defs, or assets were created, and RimWorld was not launched.

This map turns the [first playable contract](../FIRST_PLAYABLE_CONTRACT.md) and the approved [scenario lineup](../SCENARIOS.md) into a Phase 1 inspection route. It distinguishes what the pinned local RimWorld 1.6 files actually show from the implementation details that still need source-level inspection and a small in-game prototype. API names below are leads, not a guarantee that a proposed Rimrooms design is correct.

## Pinned local source target

The installed Core Def tree is under `C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Data\Core\Defs`. The managed assembly is `C:\Program Files (x86)\Steam\steamapps\common\RimWorld\RimWorldWin64_Data\Managed\Assembly-CSharp.dll`. The [RWT and gravship feasibility audit](RWT_AND_GRAVSHIP_FEASIBILITY.md#pinned-local-rimworld-test-target) records the test target, including assembly version `1.6.9676.17735` and SHA-256 `5CF1B5BE399D5B1C9C56CA72C9D35B4ECF307FEACF5859D04AC5A1AA5926356A`.

The local `Assembly-CSharp.dll` was loaded for managed metadata reflection only. Type names and signatures marked **verified metadata** below are present in that exact assembly; this does not establish runtime behavior, intended extension status, or that those APIs are stable. The local Core XML confirms Def names/shapes and examples, not C# lifecycle semantics. Neither `ilspycmd` nor `ildasm` was available on this shell's PATH, and no method bodies were inspected; follow the call chains in Phase 1 with a managed-code decompiler.

## Phase 1 source and prototype sequence

1. Reconfirm the active `Assembly-CSharp.dll` SHA-256 against the [pinned target record](RWT_AND_GRAVSHIP_FEASIBILITY.md#pinned-local-rimworld-test-target). Keep the Core XML and assembly from the same install. Do not use the current executable hash or an assembly from another RimWorld install as a substitute.
2. Open that DLL in a managed-code decompiler (for example, ILSpy) and trace only the listed call paths: scenario selection/start; site creation and map entry; power component/net lifecycle; job/work assignment and research progression; component construction and Scribe save/load; MainButton/window setup. Record exact version, type, member, caller, and source/decompiler location in this map or a linked Phase 1 record.
3. Build the smallest Core-only product spike for each route, without RWT or the 294 optional profile. Keep spikes limited to initialization, one generated site, one powered facility building, one assigned job/research project, one saved company record, and one Operations screen. Once that first Rimrooms build exists, the owner starts each in-game check through RimSort, then RimBridgeServer attaches to the disposable session as documented in the [RimBridgeServer harness](RIMBRIDGE_TEST_HARNESS.md). Keep any bridge/Harmony test tooling recorded as a harness overlay, not as a product dependency. Test save/reload and failure paths before expanding the slice.
4. After each Core route is established, add Harmony/RWT separately per the [RWT baseline plan](RWT_BASELINE_TEST_PLAN.md). Third-party APIs and behavior belong to the separate profile/source review; the 294 entries are optional and are not permission to hard-reference their content.

## Limits of this source map

This is sufficient to make the next **inspection and prototype tasks** concrete, but it does not verify constructors/factories beyond the metadata shown, intended extension points, save recovery, deterministic generation, UI behavior, or any first-slice feature in a running game. Those are Phase 1 acceptance tasks, not evidence that Gate 0 research is missing a design decision. The official [1.6 Modder Primer](https://docs.google.com/document/d/e/2PACX-1vRKE9u5ZW_zG45pxzwNvy4sxvozDeqtxlxpac5jwenOeW6liQCPgmPl9bIbtcMuqL1NPIDHOLFg64M_/pub) and local XML/metadata provide a focused route; the final design must still be based on the pinned source and observed prototype behavior.
