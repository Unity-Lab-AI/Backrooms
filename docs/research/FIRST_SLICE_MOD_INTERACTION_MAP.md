# Rimrooms - Async Industries: first-slice mod interaction map

**Status:** pre-code design and source-review map. No Rimrooms code exists and none of the checks below has been run in game. This closes only the semantic *planning* map for the Async Industries first playable; it is not a compatibility claim for the selected 294-mod profile.

## Scope and evidence rules

The scope is the [canonical first-slice inventory](../FIRST_SLICE_CONTENT_INVENTORY.md) and [first-playable contract](../FIRST_PLAYABLE_CONTRACT.md): an Async Industries Core-capable start, a five-person facility, one incomplete powered gate, one accepted onboarding survey, one AI-01 expedition of up to three pawns through one short opening, a recoverable route, one recording/evidence item, a local analysis/research follow-up, and one branch-local contract payout. The first slice does not include alternate starts, new hires, prisoner interviews, entity capture, outposts, gravships, DLC-specific progression, or co-op.

The [feature traceability map](../FEATURE_TRACEABILITY.md) owns the feature IDs and candidate state owners. This document narrows its broad 294-row feature tags to rows whose reviewed source surface touches a named first-slice action. A row is not in scope just because its `FeatureTraceIDs` contains a broad feature label. The [294-row register](rimworld-server-mod-inventory.csv) remains the complete source-review record.

- **Source fact** means a reviewed local manifest, About.xml, publisher page, or other cited source fact recorded in that row's review. It does not mean Rimrooms support.
- **Treatment** is the register's provisional project plan: optional, configuration-only, no direct adapter, excluded, or deferred. It is not a support verdict.
- **Run** means a concrete acceptance check remains pending until an implementation and recorded game session exist. **Defer** means the feature has no first-slice integration contract; it must not be inferred from broad row tags.
- RimWorld Core is the only gameplay base for the solo first-slice path. All profile mods and all five DLC remain optional; Harmony/RWT are outside this first-slice check.

## Explicit first-slice deferrals

- **Scenario editors:** rows 64 and 85 are not part of the authored Async start; editor-created starts are deferred.
- **Separate portals:** row 218 is excluded from the gate implementation. Coexistence/world-map/save checks belong to the complete selected-profile acceptance pass.
- **World quests and guests:** rows 100/132/148 and hospitality/visitor systems do not author or resolve AI-01. Quest-generation, guest and Storefront integration is deferred with the alternate scenario/economy work.
- **Turrets, capture and containment:** no stationary defense network, prisoner workflow, capture objective, or DLC Anomaly content is required to pass the first contract. Later threat slices need their own graph/tests.
- **Outposts, travel mods, gravships, and RWT:** `RR-OUT`, `RR-SPACEFLIGHT`, `RR-MP`, Harmony/RWT workflows, five DLC pathways, and all live/shared/branch-transfer interactions remain separate acceptance surfaces.
- **Other inventory rows:** optional mods whose reviewed surface does not touch one of the named first-slice actions retain their register treatment and are not promoted into this graph by tag overlap alone. The complete 294-profile load, declared-edge graph, and broad 266-row overlap queue remain later profile/evidence work.
