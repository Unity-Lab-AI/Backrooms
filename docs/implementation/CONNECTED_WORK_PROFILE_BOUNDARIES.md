# Connected work profile boundaries

**Review date:** 2026-09-28. This is a bounded source/profile review, not an implementation or compatibility result. The 294-profile inventory is a list of local packages and review status; membership does not mean every provider is supported together. No build, gameplay, or multiplayer test was run.

## Finding

The selected profile review does not identify an installed, documented general-purpose cross-map job, pathfinding, reservation, or shared-storage provider. [The connected-colony contract](../CONNECTED_COLONY_PORTALS.md) therefore requires Rimrooms to own the portal endpoint graph and cross-map job/material adapter. RimWorld maps remain separate internally; actual pawns and items must travel, and native jobs must execute on their owning map. No third-party portal, storage framework, hauling QoL mod, or RimWorld Together substitutes for that adapter.

## Required Rimrooms boundary

1. Keep endpoint graph, open-connection lifetime, and each map's identity independent from expedition records. A mission/crew panel can remain optional organization; it cannot gate ordinary work crossing.
2. On each eligible connected route, discover actual destination jobs, create native jobs against destination-owned targets, and coordinate reservations for the original ingredients/items across map boundaries. Pawn, job, target, and item retain their real identity and owner. No virtual stock transfer or remote completion.
3. A portal close must stop new route claims and suspend/cancel affected job continuations without deleting items or returning remote pawns by magic. Reopening resumes a known space; receipts reconcile interrupted crossings once.
4. Add provider adapters only for named workgiver/storage integrations after source/API and runtime review. The base Core-only path remains mandatory; optional mods keep their normal work behavior. Maintain per-provider behavior coverage instead of a claim that “all 294” automatically interoperate.
5. Record tested rows and load order for hauling/carry, stack overrides, storage, construction/ingredients, food, research, medical care, prisoner labor and each supported modded workgiver. RWT visits/trades, vehicle travel, natural portals and the timed laboratory portal require separate acceptance routes.

## Evidence limits

This review uses the local [294-row inventory](../research/rimworld-server-mod-inventory.csv), [installed relationship register](../research/installed-mod-relationships-2026-09-27.csv), and per-mod reviews, plus [CONNECTED_COLONY_PORTALS.md](../CONNECTED_COLONY_PORTALS.md). The relationship register records package-declared dependencies/order, not gameplay APIs. This review does not inspect or certify every mod's implementation API. The [RimWorld Together review](../research/reviews/mods/3005289691-nova.rimworldtogether.md) specifically records no documented supported RWT client extension API; do not use internal classes as a guessed extension surface. Runtime interoperability remains unproven across the complete profile.
