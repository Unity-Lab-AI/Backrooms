## Cross-cutting migration and source updates

The historical 0.2.0 inventory counted **14 custom ThingDefs, 1 custom TerrainDef, 4 custom SoundDefs, 5 custom PawnKindDefs and 5 custom RecipeDefs** in the listed XML, plus custom ThingCategoryDefs `RR_FieldEquipment` and `RR_Evidence`. These are historical counts, not a statement that four custom SoundDefs remain in today's loadable package: the sound definitions/WAVs have been archived outside it. The other rows and explicit legacy content still need retirement accounting. Remove categories only after item/category references are retired. Remaining C# GetNamed/defName consumers mean deleting XML alone would leave failed lookups, invalid ThingRequests, missing scenario kinds, broken recovery filters and old-save Def resolution problems.

Before shipping removals, define and implement a one-way save migration for affected Things, map terrain, Bill recipes, starting-pawn role metadata, return anchors, saved comps and company evidence. Preserve identity, crew, cargo, observations and analysis state; convert only from fields actually present. For old saves that cannot be converted losslessly, retain a compatibility reader/Def layer or require a clearly stated new-campaign boundary.
