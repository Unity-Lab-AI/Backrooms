## Journal and failure recovery

- The component saves branch ID; each attempt saves coordinate/evidence ID, original map/cell, item reference/load ID, creation-attempt flag, quality-attempt/completion flags, registration receipt and failure key. It does not own company analysis, money or contract state.
- The creation attempt is marked **before** entering native `MakeThing`. An exception before native creation returns may leave no usable object reference; that ambiguity remains a visible blocked attempt and never grants a replacement.
- Returned unspawned originals are deep-held before native quality initialization. Quality is marked attempted before its native call and marked complete only after return with a native title/book comp. An interrupted quality call cannot be blindly repeated: it may already have randomized some native book contents. Preserve the original/save and diagnose the native/mod exception; the retry button reports that state rather than rerolling it.
- Once quality completed, retry can resume placement/registration of that same retained book. Clear-slot checks refuse pawns, corpses, buildings, items or anything that native spawning would wipe. After spawning, both the native lister and cell registry must contain the original before case registration. An already spawned original is not teleported back to the slot. A detached unspawned original after an exception is returned to the holder where possible; spawned or foreign-held originals remain where native state placed them.
- Existing company evidence is the registration receipt. It can reconcile an interrupted final journal flag by matching its saved item ID without creating, moving or analyzing anything. A registered book subsequently lost, destroyed, sold or carried away remains governed by existing physical custody/loss rules. Revisiting never replaces it.
- Unknown or inconsistent component schemas stop creation actions and retain data. Duplicate saved evidence/object IDs or orphan held contents fail validation. At most **eight unfinished attempts** may be retained before new attempts stop; the first-slice site bound is smaller. Completed per-coordinate creation receipts persist because deleting them would remove the no-remint guarantee. Constructors, loading and drawing do not create, reinitialize or spawn.

### Lead-facing recovery API

`RimroomsEvidenceCreationComponent` exposes `Attempts`, `HeldCount`, `FaultKey`, `Readiness()`, `HasAttempt(evidenceId)` and `ReconcileRegistered(EvidenceRecord)`. Attempt views expose `EvidenceId`, `CoordinateId`, `Item`, `ItemLoadId`, `Registered`, `QualityComplete` and `FailureKey`. Show unresolved attempts in Operations; the retry action calls the existing **`campaign.EnsureRouteRecording(originalCoordinate)`**. Show the actual retained identity/location and explicit failure; do not offer a replacement button.

Static `CompRouteEvidence` helpers for lead recovery integration:

- `NativeCarrierDef`: validated current Core TextBook provider, or null when unavailable.
- `IsBoundRouteEvidence(Thing, string id = null)`: strict actual bound identity/count/provider check.
- `IsEvidenceCarrierPresence(Thing)`: conservative scan for deliberate legacy carriers or bound/suspect native textbooks; ordinary textbooks return false.
- `IsLegacyCarrier(Thing)` and `IsSupportedCarrier(Thing)`: explicit compatibility/provider checks.
