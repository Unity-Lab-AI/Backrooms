Determinism, and a defect in the evidence ritual found and fixed at this
checkpoint:

The .NET SDK appends the git commit to AssemblyInformationalVersion by
default. The assembly therefore embedded, literally,
"0.5.7-dev+74ce5a5594a4e17e67844a450b31f8a853e52341", which made the assembly
hash a function of the source AND the commit. Every evidence hash recorded in
this repository before this checkpoint became unreproducible the instant its
own commit was created, because creating that commit changed what a rebuild
produces. The recorded hashes were honest measurements at the time and the
clean-rebuild comparisons were real, but they could never be re-verified
afterwards, which is most of the value of recording them.

Fixed by setting IncludeSourceRevisionInInformationalVersion to false. The
informational version is now exactly "0.5.7-dev" and the hash is a pure
function of the source.

    efa5060): same hash both times, which is the property that was previously
