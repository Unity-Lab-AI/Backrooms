# Phase 5: main-menu slideshow implementation

**Status:** source implementation is present; in-game presentation and profile acceptance remain pending. This document records the implementation and its limits, not a compatibility claim.

## Included behavior

- `RimroomsMenuBootstrap` is marked `[StaticConstructorOnStartup]`. RimWorld's startup runner invokes it from its synchronous main-thread static-constructor pass; it queues `RimroomsMenuController.EnsureStarted` through `LongEventHandler.ExecuteWhenFinished`. The controller checks `UnityData.IsInMainThread` immediately before creating its persistent Unity object. The mod content constructor does not attempt Unity startup. During the entry screen the controller claims an ordinary native `UI_BackgroundMain` only when its selected texture is a known Core/DLC background. It restores the original object only while it still owns the manager slot; another renderer or an unrecognized image makes it yield for that menu entry.
- `RimroomsMenuBackground` derives from `UI_BackgroundMain`, calls the native expansion-fade setup, and uses the native draw path. It displays the two original package textures for 30 seconds each with a quiet two-second fade and no audio. Missing images, a disabled slideshow, or a failed installation leave the native background available. Reduced motion selects a still image. Settings persist in `RimroomsSettings`.
- When Rimrooms owns the background, the renderer displays `Rimrooms - Async Industries` and the loaded assembly's informational version as separate keyed UI text at x=350, beside RimWorld's top-left version area. The version is cached once; `+build-metadata` is removed, preserving values such as `0.3.0-dev`. The image files contain no title or version text.
- The texture paths are `UI/Menu/RR_Menu_FacilityThreshold_v2` and `UI/Menu/RR_Menu_FieldSurvey_v2`. The original painted images are 1672×941. The root-owned [v2 asset record](assets/menu-art-v2.json) records prompts, hashes, dimensions and package destinations. Package copies are supplied by the root; this implementation task did not edit or copy image files. They are the approved menu-art exception under the [content reuse policy](../CONTENT_REUSE_POLICY.md).

## Ownership and known behavior

The native menu initializes and can replace its background on entry. Its menu drawer casts the manager background to `UI_BackgroundMain`, so the slideshow preserves that base type and uses the public manager slot. The controller observes the native selection while it owns the slot, allowing a changed known Core/DLC selection to become the fallback. It does not alter RimWorld preferences. A third-party custom renderer or unknown selected texture takes precedence: Rimrooms yields, restores only if it still owns the slot, and does not draw its title/version overlay while yielded. The native menu remains responsible for that screen.

The renderer pauses slideshow timing while the pointer is over the expansion-icon strip and for a short grace interval, allowing native DLC hover previews to draw without copying the native renderer or accessing its private fade state. If the pointer enters during an already-started crossfade, the incoming overlay is suppressed while paused; the outgoing image can briefly reappear at its prior blend position. This is a known visual step to check during owner-launched acceptance.

Until those observations are recorded, slideshow behavior and mod interactions are not runtime-verified.
