# Rimrooms - Async Industries: feature traceability map

**Purpose:** give every planned system a stable ID and a route through gameplay design, lore/source evidence, the 294-mod profile, DLC/RWT boundaries, visual/UI direction, planned package surfaces, and acceptance proof. All 294 profile rows have source-fact review records and proposed treatments in the linked register. All 914 declared dependency/load-order records are inventoried in the [relationship disposition matrix](research/declared-relationship-disposition-matrix-2026-09-27.csv); its classifications are metadata-based project rules, not source-code confirmation or compatibility results. This map does not claim runtime compatibility; the foundation subsection identifies the small implemented subset.

## Traceability rules

### Implemented development subset

The [0.2.0 build record](implementation/PHASE_2_BUILD_RECORD.md) maps actual source directories and per-system source reviews to stable feature IDs. It adds `RR-SCEN/RR-FAC/RR-STA` scenario and starting staff, `RR-ECO/RR-MSN` branch ledger and initial contract, `RR-GATE/RR-EXP` machine and physical crew/cargo operations, `RR-SPACE/RR-THREAT` saved first site and bounded encounter, `RR-EVD` analysis and Gate Telemetry, and `RR-UI/RR-STYLE` actionable Operations panes and original sprites. `RR-COMPAT` remains the Core compiler/package route, with no optional integration clearance. No feature has runtime acceptance from compilation. Full tables below describe the complete campaign target; the build record identifies its current subset and remaining work.

- This is the feature-level index. Before Gate 0, the per-mod register assigns each of its 294 rows one or more feature IDs below, exact source evidence, a proposed treatment, and an explicit review/evidence status. Runtime compatibility remains pending until reproduced.
- Every source-specific lore claim needs a direct source URL and a saved review record. Mark it **source fact**, **interpretation**, **owner choice**, or **original game design**. An unreviewed video/film/source stays **Pending**.
- Every third-party mod mapping needs its exact Workshop/package ID and reviewed version. A category-level match in the preliminary workbook is not an integration result.
- For implementation, add the feature ID to the owning design contract, Def/source file checklist, save owner, UI route, and acceptance evidence. Do not make an untraceable feature.
- Leave unknowns as **Pending**. Do not infer an exact mod API, story fact, asset license, DLC requirement, or RWT capability from a title or feature label.
- Use [`SCENARIOS.md`](SCENARIOS.md) and [`FIRST_PLAYABLE_CONTRACT.md`](FIRST_PLAYABLE_CONTRACT.md) for opening/start rules, [`OPERATIONS_ACTION_CONTRACTS.md`](OPERATIONS_ACTION_CONTRACTS.md) for player commands and recovery, and [`CAMPAIGN_STATE_DICTIONARY.md`](CAMPAIGN_STATE_DICTIONARY.md) for state ownership, stable IDs, transfer receipts, and migrations. These are design contracts, not implementation evidence.

## Cross-feature defaults and ownership

- All three scenario starts support a complete RimWorld Core solo campaign. All five DLC and every other entry in the 294-row profile are optional. Harmony and RimWorld Together (RWT) are required only for co-op.
- A player's facility, staff, ledger, research completion, discoveries, coordinate records, expedition maps, contracts, and case records belong to that player's save branch. A visit or item exchange does not make those records shared.
- Cross-player actions are conditional on the pinned RWT build and settings. Direct trade and gifts require both players online in the documented RWT route. Offline shipments and visits remain unpromised until reproduced. A dossier or case report transferred as an item is a copy; the sender's case record remains in the sender's branch.
- State-owner entries below are **candidate design ownership**, not a claim that code exists or that a specific RimWorld/RWT extension point has been proven. Map and pawn state follows the normal owning RimWorld object; Rimrooms campaign records remain branch-local.
- The 294-row profile is a review and test target, not a requirement to install or distribute all mods. Use only public, verified extension points; do not copy third-party code or assets.

| RR-DLC | DLC content remains conditional on the installed expansion; Rimrooms progression and fallback behavior remain owned by the local campaign branch. |
| RR-SPACEFLIGHT | Vanilla Expanded gravship content owns the ship, crew and native gravship state. Rimrooms owns its branch-local mission/logistics link and any separately receipted cargo transfer. |
| RR-COMPAT | The running profile and its recorded build determine integration availability; each integration reports its local status without becoming campaign authority. |
| RR-UI | Panels are views only. Commands must update the feature's authoritative owner and show unavailable or failed actions without inventing shared state. |
| RR-STYLE | Original visual/audio assets and their provenance records own no campaign state; third-party art remains reference-only unless separately licensed and approved. |
