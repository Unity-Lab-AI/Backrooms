# Rimrooms - Async Industries: feature traceability map

**Purpose:** give every planned system a stable ID and a route through gameplay design, lore/source evidence, the 294-mod profile, DLC/RWT boundaries, visual/UI direction, planned package surfaces, and acceptance proof. This is a preparation artifact. It does not claim that a source has been reviewed, a mod is compatible, or code exists.

## Traceability rules

- This is the feature-level index. The per-mod register must assign each of its 294 rows one or more feature IDs below, a final disposition, exact source evidence, and a review status before Gate 0 passes.
- Every source-specific lore claim needs a direct source URL and a saved review record. Mark it **source fact**, **interpretation**, **owner choice**, or **original game design**. An unreviewed video/film/source stays **Pending**.
- Every third-party mod mapping needs its exact Workshop/package ID and reviewed version. A category-level match in the preliminary workbook is not an integration result.
- For implementation, add the feature ID to the owning design contract, Def/source file checklist, save owner, UI route, and acceptance evidence. Do not make an untraceable feature.
- Leave unknowns as **Pending**. Do not infer an exact mod API, story fact, asset license, DLC requirement, or RWT capability from a title or feature label.

## Gate 0 completion columns for the 294-row register

These columns have been added to the authoritative workbook and source inventory CSV. All 294 rows currently use explicit pending placeholders. Before Gate 0 can pass, replace those placeholders with verified per-row results:

1. `FeatureTraceIDs` — one or more IDs from this document, or `None—verified unrelated` with reason.
2. `ReviewRecord` — relative path to the exact review note.
3. `ReviewStatus` — `Pending`, `Reviewed—source facts recorded`, or `Runtime tested—profile details recorded`.
4. `FinalDisposition` — native feature, configuration-only, optional adapter, compatibility patch, verified alongside/no touch, or unsupported/conflict.
5. `EvidenceBuild` — exact version/build/config used; blank only while pending.
6. `AcceptanceEvidence` — test/save/log/report path or explicit `Not runtime tested`.

Each reviewed feature row also needs its approved source/style note, implementation surface, state owner, interface route, failure/recovery behavior and acceptance evidence. Update the workbook and CSV together, preserve source columns, and never promote a preliminary mapping to “supported” without evidence.
