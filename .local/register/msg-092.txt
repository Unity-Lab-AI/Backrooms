A gate has a size (0.9.2-dev)

Owner direction: "ther are 1x1 1x2 and 1x3 and 2x3 gate doors that
allow differnt capabilities as to the universe and scerios needs".

The plan assumed Core ships only 1x1 doors, so every wider gate would
have to be a run of adjacent ones. Reading the installed game data
instead found Building_MultiTileDoor and two defs using it: Core's
OrnateDoor at 2x1 and Anomaly's SecurityDoor at 2x1. The class chain
Building_MultiTileDoor : Building_SupportedDoor : Building_Door was
confirmed by decompiling. A 1x2 gate needs no mods at all.

Enumerating the installed Doors Expanded copy produced the rest:
PH_DoorDouble and PH_AutodoorDouble at 2x1, PH_DoorTriple and
PH_AutodoorTriple at 3x1, PH_DoorThickBlastDoor at 3x2, which is
exactly the 2x3 named. The four sizes line up one for one with doors
that already exist. Their defs are patched behind a
PatchOperationFindMod, which applies nothing when the mod is absent
and modifies none of its files when it is present.

Width and footprint are tracked separately, because a 2x3 blast door
is three wide but six cells of machine. Opening draw and spin-up work
scale on cell count, so a bigger gate costs more to run and is a thing
a branch works toward.

Throughput is not capped. Owner direction: "in vinilla any number of
pawns can use a door at once so we dont want limitations". A wide gate
gets more doorway cells and ordinary pathfinding spreads people across
them. OrderCrossing was checked first and only ever refused the same
pawn twice, so the correct action was to add nothing.

Rebinding is refused while a gate is ramping as well as while it is
open, per "gate doors expansions can NOT be done on a working gate".

Supported providers are declared in the patch file rather than named
in code: the component is only ever attached by our own patches, so
carrying it is the allowlist, and only the shape is enforced in code.

check-package-integrity.py correctly failed the seven Doors Expanded
targets, having no concept of optional compatibility. A target inside
a PatchOperationFindMod is optional by construction; the check now
exempts exactly those and still reports them as notes. The exemption
was proved narrow by planting a bogus target outside FindMod and
confirming it still fails.

156 C# source files, 79 approved package files. Zero warnings, zero
errors. Assembly SHA-256 reproduced by two clean recompiles. All four
checkers pass, 1,201 keyed references resolving. No new gameplay def,
asset or work type. No game launched, no test run, no RimSort profile
touched.
